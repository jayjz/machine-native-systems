# E4.1 — minimum sufficient semantic state

Preregistered October 4, 2026, before implementation/execution. Baseline: remote E4 `dffa582a3fe7f2445617e22a87d4c7ed2c0ea480`; its tree is identical to local `feb2fc4`. No new literature retrieval.

## Design and expected outcomes

Reuse E4's 20 fixtures, producers, version consumers, styles, world, complete authority mediation, decision function, audit and replay. No fixture, registry, permission, evidence, or effect semantics change. Cross all 16 subsets of the four omitted fields (alternatives, attempt, status, receipt) with optimistic and conservative defaults: 32 arms. This includes the five requested comparisons and disambiguates whether status or receipt is also necessary. Full JSON is an additional reference. Two producer adapters × two consumer policies × two styles remain crossed. They are scripted, not learned.

Optimistic defaults are exactly E4's: alternatives=[], attempt=null, status=proposed, receipt=null. Conservative missing alternatives is unknown (null); missing attempt is an explicit reserved unknown-attempt sentinel, causing the unchanged consumer to seek evidence and remain unresolved; missing status is unknown (null). A missing receipt reference imposes no reference constraint: an independently matching receipt found by exact attempt identity is sufficient under E4's existing policy. It does NOT certify receipt absence. Unknown attempt is not known absent. The sentinel cannot name a receipt in this closed world. This is an adapter policy, not a change in authority or execution. Conservative fields are inserted only after version validation. Full reference uses the original decoder unchanged.

Expected: optimistic empty compact replicates E4's six failures/two duplicates. Conservative compact prevents duplicate effects but loses useful completion; restoring ambiguity alone should still leave prior-state uncertainty; restoring attempt alone leaves intent uncertainty. Restoring both might recover prior attempts but still withhold fresh proposals because status remains unknown. We predict status plus both will match full decisions without a receipt reference. These are predictions, not observed results.

## Predeclared measures and criteria

- Exact oracle agreement, useful completion, replay recovery, field mismatches, authority violations, false verification, duplicate effects, bytes, reads, encode/decode/decision latency: E4 definitions. Unsupported-version field unavailability reported separately.
- Useful completion requires the original expected completed/confirmed outcome; safe nonexecution alone is not useful completion. Version-compatible reference has four eligible fixtures; strict v1 has three. Abstention cost = eligible outcomes withheld (including unresolved) and extra registry reads/bytes; also record abstained/unresolved totals.
- Duplicate = more than one effect per fixture, including the preexisting effect; an extra legitimate receipt does not excuse duplication.
- A sufficient subset must match all original oracle outcomes and replay recovery with zero duplicate effects, unauthorized effects and false verification. Report minima separately by default policy/consumer. A field is conditionally necessary only if deleting it from a sufficient subset fails these criteria; provide the concrete distinguishing fixture. An unnecessary field can be omitted from a sufficient subset; this is restricted to this world and this consumer, not a universal schema requirement.
- Falsification: if conservative empty compact meets the full safe/useful criteria, reject necessity of the dropped fields here. If the predicted three-field subset fails, reject that minimum prediction. If receipt-free reconciliation fails, retain receipt or conclude the policy is inadequate. If no subset restores full behavior, investigate an adapter confound rather than claim contracts succeeded. A small fail-closed representation with lower useful completion is a safety/usefulness tradeoff, not architectural superiority.

## Confound review before implementation

Known finite fixtures, authored adapters and a trusted exact receipt registry limit claims. Exhaustive subsets eliminate selective restoration but are correlated fixture repetitions, not population samples. Conservative sentinel adds an unproductive lookup; separate this cost from cognition. Status and receipt are not interchangeable: status guards fresh execution while receipt is an optional constraint on independently looked-up evidence. Consumer ordering may make omitted fields unnecessarily expensive; minimum is relative to that fixed consumer. JSON remains fixed, so syntax is not tested. Shared gate forces permission/evidence invariants in all arms. No effect of general intelligent cognition, distributed failure, calibration or actual schema novelty is tested. Existing E4 files/reports remain unchanged. Never tune defaults after seeing outcomes.
